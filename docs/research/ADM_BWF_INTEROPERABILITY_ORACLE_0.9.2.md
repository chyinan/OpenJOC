# ADM BWF interoperability oracle report (0.9.2 candidate)

## Scope and handling

A self-authored Logic Pro ADM BWF was inspected as a read-only black-box
interoperability oracle. The media is not part of the repository. No audio,
authored names, or opaque auxiliary payload was copied. The observations below
are limited to public RIFF/WAVE, ADM XML, and CHNA structure.

The pre-fix OpenJOC comparison file was generated from
`fixtures/adm/reconstructed-scene.json`. Acceptance candidates are generated by
the project-owned `synthetic_interop_fixture` example and contain only one
second of synthetic material.

## ADM XML observations

The Logic oracle uses `ebuCoreMain` in the
`urn:ebu:metadata-schema:ebuCore_2016` namespace, with the unique
`audioFormatExtended` under `coreMetadata/format`. Its top-level counts are:

| Element | Count |
|---|---:|
| `audioProgramme` | 1 |
| `audioContent` | 1 |
| `audioObject` | 27 |
| `audioPackFormat` | 27 |
| `audioChannelFormat` / `audioBlockFormat` | 36 / 36 |
| `audioStreamFormat` / `audioTrackFormat` | 36 / 36 |
| `audioTrackUID` | 36 |

Observed ID syntax matches BS.2076 shapes: `APR_1001`, `ACO_1001`, `AO_1001`,
`AP_yyyyxxxx`, `AC_yyyyxxxx`, `AB_yyyyxxxx_zzzzzzzz`, `AS_yyyyxxxx`,
`AT_yyyyxxxx_zz`, and `ATU_vvvvvvvv`. Relationships are XML child elements,
not relationship attributes on `audioTrackUID`. Each PCM UID references an
`audioTrackFormat` and `audioPackFormat`; track formats reference stream
formats; stream formats reference channel, pack, and track formats.

The oracle contains one multichannel DirectSpeakers pack and individual object
packs. Direct-speaker blocks use explicit room-centric speaker labels and
Cartesian positions. Object blocks use Cartesian positions and `rtime` plus
`duration`. Time strings use `HH:MM:SS.fffff`, including
`00:00:00.00000` and `00:04:37.48163`.

Before the fix, OpenJOC used the 2011 namespace, non-standard programme/content
and channel/block ID lengths, omitted stream/track elements, placed
`trackIndex` and relationship attributes directly on `audioTrackUID`, and put
an `audioChannelFormat` ID into CHNA's track-reference field.

The R1 candidate uses the 2016 namespace and the complete standard ID/IDRef chain.
It keeps unbound reconstruction signals at a neutral Cartesian position and
uses `LFE1` plus an explicit Cartesian LFE position only for the separately
known Base LFE. It does not copy authored names, trajectories, or programme
timing from the oracle.

## CHNA observations

The Logic CHNA header reports 36 PCM tracks and 36 UIDs, followed by 36
40-byte `audioID` records. Track indices are 1 through 36. Every record links
one `ATU_........` to an `AT_........_..` and an `AP_........`, and those values
match the AXML relationships.

The R1 candidate uses the same public CHNA semantics for three tracks. Its records
are ordered by PCM track index and link each generated UID to the exact
generated audio-track-format and pack-format IDs. No original authored UID is
claimed or reused.

## R1 external rejection and Atmos-profile diagnosis

The exact R1 file passed OpenJOC validation but was rejected by both Logic Pro
and Dolby Encoding Engine. DEE progressed beyond the former container error and
reported:

```text
ATMOS_STORAGE_RES_FORMAT_INVALID
Found unsupported bed ID: 1.
```

The error maps directly to a Dolby Atmos Master ADM profile violation. R1 used
`AO_1001` and `AO_1002` for `Objects` elements, but the Atmos profile reserves
that low object-ID range for DirectSpeakers beds and requires `Objects` IDs to
start at `AO_100B`. R1 also represented Base LFE as a single-channel
DirectSpeakers pack; the allowed bed configurations contain no mono bed, and
5.1 is the smallest allowed configuration containing LFE.

Additional R1 omissions found during the same profile audit were required
`audioProgramme` start/end attributes, the `audioContent/dialogue` marker, and
the Dolby metadata `dbmd` chunk.

## R2 synthetic candidate

R2 contains two neutral reconstruction Objects plus a generated 5.1 transport
bed. Only the bed's LFE channel carries the known Base LFE PCM. L, R, C, Ls,
and Rs are generated silence and are explicitly disclosed as placeholders in
the adjacent report; they are not claimed as recovered authored channels.

| Order | Chunk | Header offset | 32-bit payload size | Payload position | Padded end |
|---:|---|---:|---:|---:|---:|
| 0 | `JUNK` | 12 | 64 | 20 | 84 |
| 1 | `fmt ` | 84 | 16 | 92 | 108 |
| 2 | `data` | 108 | 1,152,000 | 116 | 1,152,116 |
| 3 | `axml` | 1,152,116 | 14,785 | 1,152,124 | 1,166,910 |
| 4 | `chna` | 1,166,910 | 324 | 1,166,918 | 1,167,242 |
| 5 | `dbmd` | 1,167,242 | 6 | 1,167,250 | 1,167,256 |

R2 PCM is 48 kHz, signed 24-bit, eight channels, one second. The channel order
is L, R, C, LFE, Ls, Rs, Object 1, Object 2. Its AXML uses `AO_1001` for the
5.1 bed and `AO_100B`/`AO_100C` for the two Objects. DirectSpeakers names,
labels, Cartesian positions, pack composition, and ordering follow the public
Atmos profile's room-centric assignments.

The oracle `dbmd` outer structure is valid EBU Tech 3285 Supplement 6 and
contains segment IDs 7, 9, and 10. IDs 9 and 10 are reserved/undefined in that
public specification, so their payloads are not copied or synthesized. R2
contains only the public outer structure: version 1.0, end-segment ID zero, and
one padding byte. A later external error may demonstrate that non-public Atmos
segments are mandatory; OpenJOC will not invent them from one opaque example.

## R2 external result: structure passes, Dolby authorship provenance does not

Logic Pro successfully imports R2 as three project tracks: one multichannel
`OpenJOC Generated 5.1 Bed` plus two mono reconstructed Objects. This closes the
Logic ADM interoperability gate for the tested structure.

DEE also progresses through ADM parsing, but rejects the source with:

```text
Content was not authored with Dolby tools.
```

This is no longer a RIFF, ADM, bed-ID, track-layout, or CHNA error. It is a
Dolby authoring-provenance policy. The Logic oracle contains reserved DBMD
segments 9 and 10, while R2 deliberately contains no reserved/private segment.
OpenJOC cannot truthfully assert that reconstructed content was authored with a
Dolby tool and will not clone or reverse-engineer that attestation.

The maintainer completed the controlled operational follow-up: Logic imported
R2, re-exported a new ADM BWF, and DEE accepted the Logic-authored re-export.
This verifies the production workflow without asserting that the byte-exact
OpenJOC file passes DEE directly.

## Implemented contract and gates

- Small/representable exports: exact `RIFF/WAVE` sizes with a leading 64-byte
  `JUNK` long-file reserve.
- Oversized exports: `RF64/WAVE`, first `ds64`, 32-bit sentinels, checked
  64-bit RIFF/data/sample counts, and a validated table length.
- Reader compatibility: RIFF, RF64, and legacy BW64 are parsed independently;
  unknown chunks are boundary-checked and skipped.
- PCM remains seek-skipped during validation; only bounded AXML, CHNA, and DBMD
  are retained.
- Dolby profile validation covers required programme/content metadata,
  continuous IDs, `AO_100B` object range, allowed bed configurations,
  room-centric speaker assignments, one-to-one Track/Stream/UID/CHNA links,
  and the public EBU DBMD envelope/checksums.
- Semantic claims remain unchanged: original ADM master recovery and lossless
  round trip are false, binding remains unresolved, and bound dynamic-object
  count remains zero.
